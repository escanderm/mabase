# MaBase

> **Это README-цель.** Так проект должен выглядеть, когда будет готов.
> Кода сервера ещё нет: есть замысел (`design.md`) и два прототипа
> (`prototypes/`). Пример ниже не запустится.

Бэкенд для своих проектов в одном файле. Документы с Mongo-запросами,
действия и хуки на TypeScript, правила доступа, вход по паролю и встроенный
WebSocket. Как PocketBase, только на TypeScript целиком.

```ts
// mabase.config.ts
import { defineConfig, defineCollection, defineAction, z } from 'mabase'

const notes = defineCollection('notes', {
  schema: z.object({ ownerId: z.string(), text: z.string().min(1) }),
  indexes: ['ownerId'],
  fields: { readonly: ['ownerId'] },
  rules: {
    list: (user) => (user ? { ownerId: user.id } : false), // видишь только своё
    create: (user) => !!user,
  },
  hooks: { beforeCreate: ({ doc, user }) => ({ ...doc, ownerId: user!.id }) },
})

const clearNotes = defineAction('clearNotes', {
  handler: async ({ user, db }) => {
    for (const n of await db.notes.find({ ownerId: user.id })) await db.notes.remove(n._id)
  },
})

export default defineConfig({ collections: [notes], actions: [clearNotes], realtime: true })
```

```ts
// в браузере
const mb = createClient('http://localhost:8090')
await mb.auth.login({ email, password })
mb.live('notes', {}).subscribe((list) => render(list)) // список обновляется сам
await mb.c.notes.insert({ text: 'Купить хлеб' })        // и тут же появится в list
await mb.action('clearNotes')                           // атомарно, одной транзакцией
```

## Попробовать за минуту

```bash
curl -L https://github.com/<owner>/mabase/releases/latest/download/mabase-macos-arm64 -o mabase
chmod +x mabase
./mabase serve
```

Ни Node, ни Bun ставить не нужно: всё внутри одного файла. Рядом появится
`mb_data/` с базой.

Структура проекта:

```
my-project/
  mabase               # бинарник
  mabase.config.ts     # коллекции, действия, события
  mb_hooks/            # хуки и обработчики событий
  seed.ts              # тестовые данные: ./mabase seed
  mb_data/             # создаётся сам
    db/                # база - не трогать руками
    types.d.ts         # типы для редактора
```

## Главное за пять минут

### 1. Действия - здесь живёт бизнес-логика

Действие - функция, которую вызывает клиент. Всё внутри - **одна
транзакция**: либо сохранилось всё, либо ничего.

```ts
defineAction('acceptInvite', {
  input: z.object({ inviteId: z.string() }),          // проверяется до запуска
  handler: async ({ input, user, db }) => {
    const inv = await db.invites.findOne({ _id: input.inviteId, to: user.id })
    if (!inv) throw new ActionError('not_found', 'Приглашение не найдено')
    await db.invites.remove(inv._id)
    await db.rooms.update(inv.roomId, { $push: { participants: user.id } })
  },
})
```

Пишите логику действиями, а не цепочками "поле изменилось -> хук
сработал". Через полгода вы скажете себе спасибо.

**Внешние вызовы** (`fetch`, письма) - до первого обращения к базе, в
`after*` или через отложенное событие. Пока действие работает с базой, оно
держит очередь записи всей базы, поэтому у него таймаут 2 секунды.

### 2. Коллекции и правила

- Документы как в Mongo. Схема на zod - по желанию; проверяется при записи.
- Запросы: `$eq $ne $gt $gte $lt $lte $in $nin $exists $regex $and $or $not`,
  точечная нотация. Обновления: `$set $unset $inc $push $pull`.
- `_id` - ULID: сортировка по `_id` = порядок создания.
- Пагинация: `find(filter, { sort: { _id: -1 }, limit: 50 })` и курсор
  `{ _id: { $lt: last } }`.

**Правила** `list` и `view` возвращают **фильтр**, а не да/нет. Сервер
добавляет его к запросу клиента - поэтому работают индексы, пагинация и
подписки по одним и тем же правилам.

**Поля:** `readonly` - клиент не пишет, `immutable` - задаётся при создании
и больше не меняется, `private` - видит только владелец, `hidden` - никогда
не уходят наружу. Фильтровать можно только по видимым полям.

Правило читает другую коллекцию (например, "сообщения комнат, где я
участник")? Укажите `dependsOn: ['rooms']` - и выгнанный из комнаты сразу
перестанет видеть её сообщения, в том числе в открытых подписках.

### 3. Realtime

- `mb.live(collection, filter, options)` - список, который обновляется сам.
  Если правила перестали пускать к записи - она исчезает из списка.
- После обрыва связи SDK сам перечитывает данные. Гарантии доставки событий
  нет: источник истины - база.
- `mb.emit('typing', ...)` - эфемерные события от клиента. Только те, что
  явно разрешены в конфиге, со схемой.
- Кто онлайн - живая выборка по `_presence`.

### 4. Хуки

`before*` - внутри транзакции: проверить или поправить документ. Ошибка в
`before*` отменяет всю транзакцию.

`after*` и `on(event)` - после сохранения. Могут потеряться, если процесс
упадёт в этот момент. Поэтому деньги, остатки и счётчики, которые нельзя
пересчитать, - в действии; письма и вебхуки - через отложенное событие:

```ts
emit('invite.email', { inviteId }, { after: '0s', key: `invite:${inviteId}` })
```

Отложенное событие сохраняется в той же транзакции. Доставка - **минимум
один раз**: обработчик должен спокойно переносить повтор.

### 5. Посмотреть, что происходит

```bash
./mabase tail
```

Каждая транзакция, событие и хук, сколько заняли, кто кого вызвал и сколько
миллисекунд транзакция держала очередь записи. Лучший способ найти медленный
хук.

## Ограничения - честно

- **Вся база в памяти.** ~1 КБ памяти на документ (замер на документах
  ~250 байт). VPS с 1 ГБ - примерно 300-400 тыс. документов с запасом.
  100 тыс. стартуют за 0.2 с, 1 млн - за 6 с и 1.3 ГБ.
- **Один процесс-писатель.** Второй процесс на той же папке получит ошибку.
  Масштабирования и репликации нет и не будет.
- **Запись** - около 1700 транзакций в секунду с fsync, пачками - около
  80 тыс. документов в секунду. Хватает для своих проектов с запасом.
- **Файлы** хранятся на диске рядом с базой, не в памяти.
- **Админки** в первой версии нет: сиды и REST-клиент.

## Надёжность

- Запись подтверждается только после fsync строки журнала.
- Транзакция атомарна, даже если затрагивает несколько коллекций.
- Падение процесса в любой момент не теряет подтверждённое и не оставляет
  половину транзакции. Проверено тестами с `kill -9`.
- Если файлы базы выглядят странно (нет `CURRENT`, устаревший `CURRENT`),
  MaBase **отказывается стартовать и ничего не удаляет**.
- Бэкап: `./mabase backup <папка>` - работает и на запущенном сервере
  (команда ещё не спроектирована).
