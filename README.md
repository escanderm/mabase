# MaBase

[![tests](https://github.com/escanderm/mabase/actions/workflows/ci.yml/badge.svg)](https://github.com/escanderm/mabase/actions/workflows/ci.yml)

Бэкенд и база данных в одном исполняемом файле. Внутри:
- документная база с транзакциями и журналом на диске;
- правила доступа, вход пользователей (пароль, телефон, Google, GitHub) и письма;
- HTTP API, realtime через WebSocket и SDK для браузера;
- админка.

Ничего ставить не нужно: скачали файл, запустили.

Логику приложения можно задавать двумя путями, и они работают вместе:

- **из админки** - коллекции, индексы, способы входа, почта;
- **из кода** - `mabase.config.ts` и папка `mb_hooks/` на TypeScript: схемы,
  правила доступа, хуки, действия, события.

Пример готового приложения - чат с комнатами в [`chat/`](chat).

## Установка

Сборки - в [релизах](https://github.com/escanderm/mabase/releases):

| Платформа | Файл |
|---|---|
| macOS, Apple Silicon | `mabase-darwin-arm64.tar.gz` |
| macOS, Intel | `mabase-darwin-x64.tar.gz` |
| Linux x64 | `mabase-linux-x64.tar.gz` |
| Linux ARM64 | `mabase-linux-arm64.tar.gz` |

```bash
curl -L https://github.com/escanderm/mabase/releases/latest/download/mabase-linux-x64.tar.gz | tar -xz
./mabase version
```

- Суммы sha256 - в `checksums.txt` того же релиза.
- Для Linux нужна glibc: проверено на Ubuntu 22.04, Alpine (musl) не подойдёт. Windows не поддерживается.
- macOS не даёт запустить файл, скачанный браузером. Снимите метку карантина: `xattr -d com.apple.quarantine mabase`. После `curl` такой метки нет.

Обновление: `./mabase update`. Команда:
1. скачивает последний релиз;
2. сверяет sha256;
3. проверяет, что новый файл запускается;
4. только после этого заменяет старый.

Данные не трогает. `./mabase update --check` - только узнать, есть ли новая версия.

## Первый запуск

```bash
mkdir my-app && cd my-app
./mabase serve
```

Рядом появится папка `mb_data/` с базой. Пока нет ни одного администратора,
MaBase проводит первичную настройку из трёх шагов:

1. **Администратор** - email и пароль для входа в админку.
2. **Как входят пользователи** вашего приложения - email и пароль, телефон,
   Google, GitHub.
3. **Почта** - SMTP-сервер или печать писем в консоль (для разработки).

Запустили из терминала - вопросы появятся прямо там:

```
Первый запуск MaBase - настроим за минуту. Всё можно поменять потом в админке.

Email администратора: me@my.app
Пароль (не короче 10 символов): ************
Пароль ещё раз: ************
  Администратор me@my.app создан.

Как входят пользователи вашего приложения?
  1. Email и пароль
  2. Телефон (код через authphone.su, без SMS)
  3. Google
  4. GitHub
Номера через запятую [1]: 1
...
Готово. Админка: http://127.0.0.1:8090/_/ - войдите как me@my.app
```

Запустили без терминала (systemd, Docker) или нажали Enter на первом
вопросе - сервер напечатает одноразовую ссылку. Тот же мастер откроется по
ней в браузере:

```
(!) Администратора ещё нет. Откройте ссылку, чтобы создать первого:
    http://127.0.0.1:8090/_/#/setup/...
```

Ссылка работает, пока не создан первый администратор. Ещё способ - из
командной строки на машине сервера:
`./mabase superuser upsert me@my.app <пароль>`.

Что лежит в папке проекта:

```
my-app/
  mabase               # сам MaBase
  mabase.config.ts     # необязательно: коллекции, правила, действия из кода
  mb_hooks/            # необязательно: хуки и обработчики событий (*.ts)
  mb_public/           # необязательно: фронтенд, сервер отдаёт его как статику
  seed.ts              # необязательно: тестовые данные, ./mabase seed
  mb_migrations/       # необязательно: миграции, ./mabase migrate
  mb_data/             # создаётся сам
    db/                # база: журнал и снапшот - руками не трогать
    secret.key         # ключ подписи токенов и шифрования настроек - берегите
    admin.json         # адрес и токен для команд CLI, пока сервер работает
```

## Настройки: что где

Три источника, и у каждого своё место:

| Что | Где задаётся |
|---|---|
| Коллекции, схемы, правила, хуки, действия, события, cron | `mabase.config.ts`, `mb_hooks/` - это код |
| Порт, хост, папка данных, статика, публичный адрес, CORS | переменные окружения, `.env` или флаги |
| Секреты: `MABASE_SECRET`, S3, SMTP, Google/GitHub | `.env` (не в git) или админка (шифруются `secret.key`) |
| Способы входа и почта «на ходу» | админка `/_/` |

**Приоритет:** флаги CLI > env > `mabase.config.ts` > настройки админки >
умолчания. Одно значение - один победитель, и `mabase config` его показывает.

Локально достаточно одного файла: `.env` рядом с бинарником (Bun читает его
сам), шаблон - [`.env.example`](.env.example). Коллекции в env не задаются:
это код, он живёт в конфиге и проходит ревью.

```
$ ./mabase config
MaBase 0.2.8: настройки (слева - значение, справа - откуда оно)
  папка данных         /opt/my-app/mb_data            (по умолчанию)
  порт                 9000                           (MABASE_PORT)
  хост                 127.0.0.1                      (MABASE_HOST)
  публичный адрес      https://my.app                 (MABASE_SERVER_URL)
  CORS                 https://my.app                 (config)
  секрет подписи       есть (файл)                    (mb_data/secret.key)
  файлы                S3 my-files @ storage.yandexcloud.net/myapp, ключ ***  (MABASE_S3_*)
  почта                SMTP smtp.example.test:587, пароль ***                 (MABASE_SMTP_*)
  вход                 password, authphone; OAuth: google                     (config)
  коллекции            notes, messages (2)            (config)
  хуки                 a.ts, digest.ts (2)            (mb_hooks/)
```

| Переменная | Что |
|---|---|
| `MABASE_DIR`, `MABASE_PORT`, `MABASE_HOST` | папка данных, порт, адрес |
| `MABASE_PUBLIC`, `MABASE_SERVER_URL`, `MABASE_CORS` | статика, публичный адрес, источники CORS |
| `MABASE_SECRET` | ключ подписи токенов вместо `mb_data/secret.key` (не короче 32) |
| `MABASE_S3_BUCKET`, `_REGION`, `_ACCESS_KEY_ID`, `_SECRET_ACCESS_KEY`, `_ENDPOINT`, `_PREFIX`, `_PATH_STYLE`, `_SESSION_TOKEN` | файлы в S3 |
| `MABASE_SMTP_HOST`, `_PORT`, `_USER`, `_PASS`, `_SECURE`, `MABASE_MAIL_FROM` | почта |
| `MABASE_APP_URL`, `MABASE_GOOGLE_ID/SECRET`, `MABASE_GITHUB_ID/SECRET` | вход |
| `MABASE_UPDATE_URL` | свой сервер обновлений вместо GitHub |

- Неизвестная `MABASE_*` - предупреждение при старте (опечатка не молчит).
- Кривое значение - ошибка с именем переменной, а не загадка позже.
- S3 можно задать частично в env, а остальное - в конфиге.
- Секреты в env видны в `docker inspect` и `/proc/<pid>/environ`: на сервере
  кладите `.env` с правами 600 или используйте секрет-менеджер.

## Админка

`http://<сервер>:8090/_/` - вход по email и паролю администратора.

- **Обзор** - версия, число документов, память, размер журнала;
  компактирование и бэкап.
- **Коллекции** - список слева с числом документов. "+ создать" - новая
  коллекция с индексами.
- **Документы:**
  - строка фильтра: `{ status: 'new', total: { $gt: 100 }, email: /@my\.app$/i }`;
  - сортировка, выбор полей, страницы;
  - план запроса: через индекс или перебор, сколько документов просмотрено;
  - вид списком, JSON или таблицей;
  - правка, вставка, клон, удаление, удаление по фильтру;
  - живой режим: список обновляется сам.
- **Схема** - какие поля реально лежат в документах: типы, доля документов
  с полем, примеры значений.
- **Индексы** - у коллекций из админки правятся здесь же, у коллекций из
  кода - только просмотр.
- **Правила** - правила доступа исходным кодом, виды полей, схема.
- **Журнал** - живой поток: транзакции, действия, события, письма, ошибки.
- **Администраторы** - добавить, сменить пароль, удалить.
- **Настройки:**
  - способы входа пользователей;
  - почта, с проверочным письмом;
  - раздел "База": служебные поля и лимиты запросов.

Как работают изменения из админки:
- **правила доступа не применяются**, но хуки и схемы коллекций работают;
- каждая правка видна в журнале с email администратора;
- поля с видом `hidden` (например, `passwordHash`) админка не видит и не меняет.

Настройки хранятся в самой базе и применяются сразу, без перезапуска.
Секреты (Client Secret, пароль SMTP) хранятся зашифрованными ключом из
`secret.key` и наружу не отдаются. Если тот же раздел (`auth` или `mail`)
задан в `mabase.config.ts`, работает код, а админка показывает его только для
чтения.

Выключить админку: `admin: { enabled: false }` в `mabase.config.ts`.

## Данные

### Коллекции и документы

Документ - JSON-объект. В каждом документе любой коллекции есть служебные
поля, их ставит сервер:

| Поле | Тип | Что это |
|---|---|---|
| `_id` | string | ULID - уникальный, сортировка по нему = порядок создания. При вставке можно задать свой |
| `_createdAt` | number | когда создан, мс с 1970 (`Date.now()`) |
| `_updatedAt` | number | когда изменён последний раз, мс |

Остальные поля - любые значения JSON. Время храните числом (`Date.now()`).
Схема полей необязательна. Если задать её (zod, в `mabase.config.ts`), она
проверяется при каждой записи.

Откуда берутся коллекции:

| Откуда | Как появилась | Что можно в админке |
|---|---|---|
| из кода | `defineCollection` в `mabase.config.ts` | документы; индексы и правила - только просмотр |
| из админки | "+ создать" | документы, индексы, удаление |
| только данные | хук или действие пишет в `db.<имя>` без описания | документы, удаление |
| служебные | начинаются с `_`, их ведёт MaBase | просмотр и осторожная правка |

**Клиентам (SDK, HTTP) коллекция закрыта, пока у неё нет правил доступа.**
Правила - функции, поэтому задаются в коде. Код, который их открывает, админка
показывает на вкладке "Правила".

Служебные коллекции:

| Коллекция | Что хранит |
|---|---|
| `users` | пользователи приложения: `email`, `phone`, `passwordHash`, `verified`, `roles` и ваши поля |
| `_authTokens` | сессии пользователей и одноразовые токены писем (только хэши) |
| `_externalAuths` | привязки к Google и GitHub |
| `_presence` | кто сейчас подключён по WebSocket |
| `_scheduled` | отложенные события |
| `_superusers`, `_superuserSessions` | администраторы и их сессии - в админке не показываются |
| `_settings`, `_collections` | настройки и коллекции из админки - в админке не показываются |

### Запросы

Фильтр - JSON-объект:

```js
{ status: 'new' }                          // равенство
{ total: { $gte: 100, $lt: 500 } }         // диапазон
{ status: { $in: ['new', 'paid'] } }       // одно из
{ 'address.city': 'Москва' }               // вложенное поле через точку
{ tags: 'sale' }                           // массив содержит значение
{ email: { $regex: '@my\\.app$', $options: 'i' } }
{ $or: [{ status: 'new' }, { urgent: true }] }
```

- Операторы: `$eq $ne $gt $gte $lt $lte $in $nin $exists $regex $options $not $and $or`.
- Обновления: `$set $unset $inc $push $pull`.
- Сортировка `{ поле: 1 | -1 }`, `limit`, выбор полей.
- Постраничный вывод - курсором по `_id`:
  `find({ _id: { $lt: последний } }, { sort: { _id: -1 }, limit: 50 })`.
- Вложенные массивы раскрываются: `{ a: 1 }` находит `a: [[1, 2]]`.
- `$set` во вложенное поле через скаляр - ошибка (как в Mongo): `{ a: 'x' }` и
  `{ $set: { 'a.b': 1 } }` не превращают строку в объект. Номер элемента
  массива задать можно: `$set: { 'tags.0': 'x' }`.
- Имена `__proto__`, `constructor` и `prototype` в путях фильтра, сортировки,
  `fields` и обновлений запрещены: это не поля документа.

### Файлы

Поле-файл объявляется в коллекции, значение поля - id файла:

```ts
const users = defineCollection('users', {
  files: {
    avatar: { maxBytes: 2 << 20, accept: ['image/'] },   // одно значение
    photos: { many: true, maxBytes: 10 << 20 },          // массив
  },
})
```

- **Загрузка - в том же запросе, что и запись:** `POST /api/c/:c` и
  `PATCH /api/c/:c/:id` с `multipart/form-data`. Текстовые части - поля
  документа (значение - JSON), файловые - в объявленные поля.
- **Отдача:** `GET /api/files/:id` - файл виден, только если видна запись, к
  которой он приложен (правило `view` её коллекции). `?download=1` - как
  вложение. Ссылка: `mb.fileUrl(id)`.
- **Замена и удаление** записи убирают старые файлы.
- **Лимиты:** `http.maxUploadBytes` (100 МБ), `files.<поле>.maxBytes`,
  `files.<поле>.accept` (префиксы mime; тип выводится из имени файла, так что
  это удобство, а не защита - содержимое проверяйте сами).
- В документе лежит только id: имена, размеры и типы - в служебной `_files`.
- **Докачка (Range):** `GET /api/files/:id` понимает `Range: bytes=...` -
  ответ `206` с `Content-Range`, для куска за концом - `416` с `bytes */размер`.
  Срез читается только нужными байтами: и из локальной папки, и из S3
  (заголовок `Range` уходит в облако), файл не поднимается в память целиком.
- **Из админки:** в диалоге записи видны поля-файлы - текущие (скачать,
  удалить) и загрузка. Файл кладётся сразу, без «Сохранить». Админка ходит
  в `/api/_/files/...` под токеном администратора (правила `view` - для
  клиентов), ссылку с токеном в адрес не кладём: скачивание идёт blob-ом.

**S3 вместо диска.** Байты можно хранить в S3-совместимом облаке (AWS, MinIO,
Cloudflare R2, Яндекс) - метаданные всё равно в базе:

```ts
// mabase.config.ts
export default defineConfig({
  storage: {
    s3: {
      bucket: 'my-files',
      region: 'ru-central1',
      accessKeyId: process.env.S3_KEY!,
      secretAccessKey: process.env.S3_SECRET!,
      endpoint: 'https://storage.yandexcloud.net', // нет - AWS
      prefix: 'myapp',            // необязательно: общий префикс ключей
      forcePathStyle: true,       // для MinIO и большинства S3-совместимых
    },
  },
})
```

- Запросы к S3 подписываются AWS Signature V4 (своими руками, без зависимостей).
- Ключ объекта: `[prefix/]<коллекция>/<запись>/<id файла>-<имя>`.
- Удаление записи удаляет и объекты в S3.
- **Переключили хранилище - перенесите файлы:**

  ```bash
  ./mabase files migrate --from local --to s3 --dry-run   # посчитать
  ./mabase files migrate --from local --to s3             # скопировать
  ./mabase files migrate --from s3 --to local             # обратно
  ```

  Перенос идемпотентный: что уже лежит в целевом хранилище - пропускается,
  повторный запуск безопасен. Сервер должен быть остановлен (как у `seed`).
  **Источник не удаляется:** убедитесь, что файлы отдаются, и уберите старое
  сами.
- Настройки S3 - только в `mabase.config.ts` (в админке их пока нет).

```js
const doc = await mb.c.users.insert({ name: 'Алиса' }, { files: { avatar: input.files[0] } })
img.src = mb.fileUrl(doc.avatar)
```

### Связи

Связь - поле, в котором лежит `_id` документа другой коллекции (или массив
`_id`). Объявленная связь даёт три вещи:

1. **Проверка при записи:** документа с таким `_id` нет - запись
   отклоняется (400). `null` и отсутствие поля - можно.
2. **Что делать, когда связанный документ удаляют** (`onDelete`):

   | Значение | Что происходит |
   |---|---|
   | `restrict` (по умолчанию) | удалить нельзя, пока на документ ссылаются (409) |
   | `cascade` | ссылающиеся документы удаляются вместе с ним |
   | `unset` | у ссылающихся поле убирается |
   | `pull` | для массива: `_id` убирается из массива |

   Всё это - в той же транзакции, что и удаление.
3. **`expand`** - связанные документы прямо в ответе:

   ```js
   await mb.c.messages.find({ roomId }, { expand: ['authorId'] })
   // [{ _id, text, authorId: 'u1', _expand: { authorId: { _id: 'u1', name: 'Алиса' } } }]
   ```

   Клиент получает связанный документ, только если правило `view` той
   коллекции его пускает. Закрытые поля той коллекции скрыты, как при
   обычном чтении. Не виден - в `_expand` будет `null`. Работает в `find`,
   `get` и `GET /api/c/...?expand=a,b`; в `live()` - пока нет.

Объявить связь:
- **в коде** - `relations` в `defineCollection`, пример ниже;
- **в админке** - вкладка "Связи" у коллекции, созданной в админке.

Админка показывает поля-связи ссылками с именем связанного документа, а у
каждого документа есть кнопка "Ссылки" - кто на него ссылается. Поля-связи
индексируются автоматически.

### Индексы

Индекс по полю ускоряет равенство, `$in`, диапазоны и сортировку по этому
полю. `limit` и `sort` тоже идут через индекс: последние 50 сообщений комнаты
из 100 тысяч - 0.05 мс. Без индекса запрос перебирает документы. Клиентам
перебор ограничен (`maxScanned`): большой запрос без индекса вернёт ошибку
"добавьте индекс", а не повесит сервер.

## Проект в коде

Всё в этом разделе необязательно: пустая папка с `mabase` уже работает.
Файлы `mabase.config.ts` и `mb_hooks/*.ts` импортируют модуль `mabase` - он
встроен в исполняемый файл, `node_modules` не нужен.

**Подсказки в редакторе.** При запуске MaBase пишет в `mb_data/types.d.ts`
типы своего API и рядом - типы zod (около 700 КБ на 125 файлов; переписываются
только при изменении). Поэтому `import { defineCollection, z, on } from 'mabase'`
подсказывается без `node_modules`, а `z.object(...)` проверяется по-настоящему.
Если у проекта есть свой `tsconfig.json`, добавьте `mb_data/types.d.ts` в
`include`.

### mabase.config.ts

```ts
import { defineConfig, defineCollection, defineAction, ActionError, z } from 'mabase'

const orders = defineCollection('orders', {
  schema: z.object({ userId: z.string(), status: z.enum(['new', 'paid']), total: z.number() }),
  indexes: ['userId', 'status'],
  owner: 'userId',                       // поле с id владельца
  fields: {
    readonly: ['userId', 'status'],      // клиент не пишет
    immutable: [],                       // клиент задаёт только при создании
    private: [],                         // видит только владелец
    hidden: [],                          // не уходит наружу никогда
  },
  rules: {
    list: (user) => (user ? { userId: user.id } : false), // фильтр: что видно в списках
    view: (user) => (user ? { userId: user.id } : false), // фильтр: что видно по id
    create: (user) => !!user,
    update: (user, { before }) => user?.id === before.userId,
    delete: false,
  },
  relations: {
    userId: { to: 'users', onDelete: 'cascade' },    // удалили пользователя - удалились его заказы
    items: { to: 'products', many: true, onDelete: 'pull' },
  },
  hooks: {
    beforeCreate: ({ doc, user }) => ({ ...doc, userId: user!.id, status: 'new' }),
  },
})

const pay = defineAction('pay', {
  input: z.object({ orderId: z.string() }),
  handler: async ({ input, user, db, emit }) => {
    const order = await db.orders.findOne({ _id: input.orderId, userId: user.id })
    if (!order) throw new ActionError('not_found', 'Заказ не найден')
    await db.orders.update(order._id, { $set: { status: 'paid' } })
    emit('order.paid', { orderId: order._id }, { after: '0s', key: `paid:${order._id}` })
  },
})

export default defineConfig({ collections: [orders], actions: [pay], realtime: true })
```

Разделы `defineConfig`:

| Раздел | Что задаёт |
|---|---|
| `collections` | коллекции; `users` - расширение встроенной |
| `actions` | действия - бизнес-логика, вызывается клиентом |
| `auth` | вход: `providers`, `signup`, `oauth`, `appUrl`, `minPasswordLength`, сроки токенов. Если задан - главнее настроек админки |
| `mail` | `smtp` или своя функция `send`, `from`, шаблоны писем. Если задан - главнее настроек админки |
| `realtime` | `true` - WebSocket `/api/realtime` |
| `events` | события для сокета: клиентские (`from: 'client'`, `input`, `allow`, `to`) и серверные |
| `limits` | лимиты запросов клиентов: `defaultLimit` 100, `maxLimit` 1000, `maxScanned` 20000, `maxRegexLength` 64; в `sort` и `fields` не больше 8 полей |
| `http` | `cors`, `trustProxy`, `serverUrl`, `publicDir`, `maxBodyBytes` |
| `db` | `txTimeoutMs` 2000, `compactMinBytes`, `bigTxOps`, `maxDepth` |
| `scheduler` | отложенные события: `maxAttempts`, `retryBaseMs`, `concurrency`, `timeoutMs` |
| `admin` | `enabled`, сроки сессий и лимит попыток входа администраторов |

Секреты не пишите в конфиг: `process.env.GOOGLE_SECRET` или файл `.env`
рядом с `mabase` (он читается сам).

### Правила доступа

Правила действуют на запросы клиентов (SDK и HTTP). Код на сервере - хуки,
действия, сид - и админка идут мимо них.

- `list` и `view` возвращают **фильтр** (или `true` - всё, `false` -
  ничего). Сервер добавляет фильтр к запросу клиента, поэтому одни и те же
  правила работают для списков, индексов, страниц и подписок.
- `create`, `update`, `delete` возвращают `true` или `false`.
- Нет правила - нельзя. Исключение - встроенная `users`: каждый видит и правит
  себя (без пароля и служебных полей); это её правила по умолчанию.
- `count` (`?count=1`) считается по правилу `list` - это число записей в
  списке. `view` не должен быть уже `list`, иначе клиент узнает и число
  записей, которые по id ему не читаются.
- Поле из `owner` клиент не пишет никогда: оно попадает в `readonly` и
  `immutable` само. Иначе `fields.private` обходился бы сменой владельца.
- Правило читает другую коллекцию (например, "сообщения комнат, где я
  участник")? Укажите `dependsOn: ['rooms']` в `rules`. Тогда при изменении
  `rooms` открытые подписки пересчитаются, и выгнанный из комнаты сразу
  перестанет видеть её сообщения. `mabase serve --dev` предупреждает, если
  `dependsOn` забыли.

### Действия

Действие - функция на сервере, которую вызывает клиент: `mb.action('pay', { orderId })`.

- **Всё внутри действия - одна транзакция:** сохранится либо всё, либо ничего.
- `input` проверяется схемой до запуска.
- По умолчанию нужен вход. Для гостей - `public: true`.
- Ошибка для клиента - `throw new ActionError(код, текст)`. Коды:
  `bad_request`, `unauthorized`, `forbidden`, `not_found`, `conflict`,
  `too_many_requests`.
- Внешние вызовы (`fetch`, письма) делайте до первого обращения к базе или
  через отложенное событие. Пока действие работает с базой, оно держит
  очередь записи, поэтому у него таймаут 2 секунды.

### Хуки

| Хук | Когда | Что может |
|---|---|---|
| `beforeCreate({ doc, user, db })` | до записи, в транзакции | вернуть изменённый документ; ошибка отменяет транзакцию |
| `beforeUpdate({ prev, next, user, db })` | до записи | то же |
| `beforeDelete({ prev, user, db })` | до удаления | ошибка запрещает удаление |
| `afterCreate`, `afterUpdate`, `afterDelete` | после сохранения | побочные действия; ошибка не отменяет запись |

В контексте хука есть `origin` - кто вызвал запись: `api` (клиент), `action`,
`hook` (запись из другого хука), `seed`, `system`. Хук, который сам пишет в
базу, получит на своё изменение `origin: 'hook'` и может его пропустить -
это дешевле, чем городить флаг в документе.

Хуки коллекций задаются в `defineCollection`. Обработчики событий - в
`mb_hooks/*.ts`:

```ts
// mb_hooks/orders.ts
import { on, mail } from 'mabase'

on('orders.created', async ({ data, db }) => { /* data.doc - новый заказ */ })

on('order.paid', async ({ data, db }) => {
  const order = await db.orders.findOne({ _id: data.orderId })
  if (order) await mail.send({ to: 'shop@my.app', subject: 'Оплата', text: `Заказ ${order._id} оплачен` })
})
```

- События записей приходят сами: `<коллекция>.created`, `.updated`, `.deleted`
  с `{ doc, prev }`.
- Свои события - `emit()` в действии или хуке.

**Правка хуков подхватывается без перезапуска:** `mabase serve` следит за
`mb_hooks/` (пауза 150 мс после записи файла). Обработчики и задачи
`schedule()` собираются заново целиком, поэтому удалённый файл перестаёт
работать. Если файл сломан, сервер продолжает работать со старыми хуками, а
ошибка уходит в журнал и `tail`. `mabase.config.ts` так не перезагружается -
для его правок нужен рестарт.

### Отложенные события

`emit('имя', data, { after: '10m', key })` сохраняет задачу **в той же
транзакции**. Обработчик `on('имя')` выполнится в указанное время.

- `key` защищает от дублей: пока задача с таким ключом ждёт, вторая не ставится.
- Ошибка - повтор с растущей паузой (5 с, 10 с, 20 с ... до часа).
  После 5 попыток задача остаётся в `_scheduled` с `failed: true`.
- **Доставка - минимум один раз:** обработчик должен спокойно переносить
  повтор.
- Задачи, время которых пришло, пока сервер был выключен, выполняются при
  старте.

### Сид

```ts
// seed.ts
import { defineSeed } from 'mabase'
export default defineSeed(async ({ db, auth }) => {
  const alice = await auth.upsertUser({ email: 'alice@example.test', password: 'dev-alice-1', name: 'Алиса' })
  await db.orders.upsert({ _id: 'o1' }, { userId: alice._id, status: 'new', total: 100 })
})
```

`./mabase seed` - при остановленном сервере. Пишите сид через `upsert`,
тогда его можно запускать повторно.

### Миграции

Нужны редко (нет `ALTER TABLE`), но «переименовать поле у всех» бывает:

```ts
// mb_migrations/202603101200-rename-title.ts
import type { Db } from 'mabase'

export async function up(db: Db) {
  for (const doc of await db.notes.find({ title: { $exists: true } })) {
    await db.notes.update(doc._id, { $set: { name: doc.title }, $unset: { title: '' } })
  }
}
```

- Имя файла - `YYYYMMDDHHMM-имя.ts`, порядок - по имени.
- `./mabase migrate` (сервер остановлен). Применённые записаны в
  `_migrations` и второй раз не выполняются.
- **Каждая миграция - одна транзакция:** упала посреди - в базе её нет.
  Уже применённые до неё остаются.
- `down` нет: откат - это новая миграция.

### Периодические задачи

```ts
// mabase.config.ts или mb_hooks/digest.ts
import { on, schedule } from 'mabase'

schedule('digest.daily', '0 9 * * *', { to: 'team' })

on('digest.daily', async ({ data, db, task }) => {
  // task.runAt - когда задача должна была выполниться
})
```

- Cron - 5 полей, локальное время сервера: `*`, числа, `a-b`, `*/n`,
  `a-b/n`, `a/n`, списки через запятую. День месяца и день недели, как в
  cron: если ограничены оба, достаточно совпадения одного.
- Задача живёт в `_scheduled` (одна на событие, `key: cron:<событие>`),
  переживает перезапуск, просроченная выполняется при старте.
- Доставка - минимум один раз, обработчик должен быть идемпотентным.
  Ошибки повторяются как у отложенных событий; после исчерпания попыток
  задача помечается проваленной, а при следующем старте ставится заново.

## Вход пользователей

Способы входа включаются в админке (Настройки) или в `auth.providers`:

| Способ | Что нужно |
|---|---|
| Email и пароль | ничего; пароль хранится как argon2id |
| Телефон | ничего: код подтверждения выдаёт сервис authphone.su, без SMS |
| Google, GitHub | Client ID и Client Secret из консоли провайдера; адрес возврата `<сервер>/api/auth/oauth/<google или github>/callback`; адрес приложения |

Что видно снаружи: занятый email сообщается и при регистрации, и при смене
email (иначе человек не поймёт, почему письмо не пришло). Сброс пароля при
этом неразличим: ответ одинаковый и по тексту, и по времени.

Как устроены сессии:
- **Токены:** access - JWT на 15 минут, refresh - на 30 дней. SDK обновляет
  access сам.
- **Смена пароля и выход** закрывают сессии сразу; открытый WebSocket
  закрывается в течение 5 секунд (сессия перепроверяется по таймеру, а не на
  каждом событии - подписка может молчать).
- **Лимиты:** 10 неверных попыток входа с одного IP за 15 минут и 50 - на
  аккаунт (чтобы чужой человек с ботнета не закрывал вход владельцу).
  `loginLimit` меняет числа.

Письма уходят через почту из настроек:
- подтверждение email;
- сброс пароля;
- смена email.

Для SMTP нужен адрес приложения: на него ведут ссылки из писем.

## Клиент в браузере

Сервер сам отдаёт SDK: ни npm, ни сборщик не нужны.

```js
import { createClient } from '/api/client.js'
const mb = createClient(location.origin)

await mb.auth.register({ email, password, data: { name: 'Алиса' } })
await mb.auth.login({ email, password })
await mb.auth.restore()                       // после перезагрузки страницы
mb.auth.onChange((user) => { /* вошёл или вышел */ })

await mb.c.orders.find({ status: 'new' }, { sort: { _id: -1 }, limit: 20, expand: ['userId'] })
await mb.c.orders.insert({ total: 100 })
await mb.c.orders.update(id, { $set: { note: 'позвонить' } })
await mb.c.orders.remove(id)
await mb.action('pay', { orderId: id })

// Живой список: обновляется сам, после обрыва связи перечитывается
const live = mb.live('orders', {}, { sort: { _id: -1 }, limit: 50 })
live.subscribe((items) => render(items))
await live.loadMore(50)                       // ещё 50 старых
live.close()

mb.emit('typing', { roomId })                 // клиентское событие (объявите в events)
mb.on('typing', ({ from, data }) => {})
```

Ошибки - `MabaseError` с полями `code` и `message`.

### Типы без генерации кода

`createClient<typeof config>` выводит типы из zod-схем конфига: коллекции,
поля документов и данные действий. Ничего генерировать не нужно.

```ts
// client.ts - тот же конфиг, что у сервера, только типом
import type config from '../mabase.config'
import { createClient } from 'mabase/client'

const mb = createClient<typeof config>(location.origin)

const msgs = await mb.c.messages.find({ roomId })   // msgs: { _id, text, roomId, ... }[]
await mb.c.messages.insert({ text: 'привет', roomId })  // не хватит поля - ошибка типов
await mb.action('invite', { roomId, email })        // вход действия проверяется
```

- В браузере `mabase/client` - это `/api/client.js` из бинарника. Подключите
  import map (или алиас в сборщике):

  ```html
  <script type="importmap">
    { "imports": { "mabase/client": "/api/client.js" } }
  </script>
  ```

- Типы `mabase/client` берутся из `mb_data/types.d.ts`, который бинарник пишет
  при старте (см. «Проект в коде»).
- Без параметра типа `createClient(url)` - обычный клиент с `Doc`, как раньше.

## HTTP API

| Путь | Что |
|---|---|
| `GET /api/health` | `{ ok: true }` |
| `GET /api/c/:коллекция` | `?filter=<JSON>&sort=<JSON>&limit=50&fields=a,b&expand=a,b` -> `{ items, tx }`; `?count=1` -> `{ count }` |
| `POST /api/c/:коллекция` | создать документ |
| `GET`, `PATCH`, `DELETE /api/c/:коллекция/:id` | прочитать, изменить операторами (`{ $set: ... }`), удалить |
| `POST /api/actions/:имя` | вызвать действие, тело - `input` |
| `/api/auth/*` | `register`, `login`, `phone`, `refresh`, `logout`, `me`, `password`, `verify-email/*`, `reset-password/*`, `change-email/*`, `oauth/*` |
| `GET /api/client.js` | SDK для браузера |
| `/api/realtime` | WebSocket: подписки, события, presence |
| `/_/`, `/api/_/*` | админка и её API |
| остальное | статика из `mb_public/` |

- Токен - в заголовке `Authorization: Bearer <access>`.
- Ошибка - `{ code, message, details? }` с HTTP-статусом:
  400, 401, 403, 404, 409, 413, 415, 429; 503, если сервер перегружен.

## Командная строка

| Команда | Что делает |
|---|---|
| `mabase serve [--port 8090] [--host 0.0.0.0] [--dev]` | запустить сервер; `--dev` - предупреждать о забытом `dependsOn` |
| `mabase files migrate --from local\|s3 --to local\|s3 [--dry-run]` | перенести файлы между хранилищами |
| `mabase seed` | выполнить `seed.ts` (сервер остановлен) |
| `mabase migrate` | применить миграции из `mb_migrations/` (сервер остановлен) |
| `mabase backup <папка>` | бэкап, в том числе на работающем сервере |
| `mabase import <коллекция> <файл.ndjson>` | импорт, пачками по 1000; документы с существующим `_id` пропускаются |
| `mabase tail` | живой журнал работающего сервера |
| `mabase superuser list \| upsert <email> <пароль> \| delete <email>` | администраторы админки |
| `mabase update [--check]` | обновиться до последнего релиза |
| `mabase version` | версия |

Общие флаги:
- `--dir mb_data` - папка данных;
- `--root .` - папка проекта;
- `--public mb_public` - папка статики.

Переменные окружения:
- `MABASE_SECRET` - ключ подписи токенов вместо `mb_data/secret.key`, не короче 32 символов;
- `MABASE_UPDATE_URL` - откуда брать обновления, для своих сборок.

## Работа на сервере

Пример для systemd:

```ini
# /etc/systemd/system/mabase.service
[Service]
WorkingDirectory=/opt/my-app
ExecStart=/opt/my-app/mabase serve --port 8090 --host 127.0.0.1
Restart=always
User=mabase

[Install]
WantedBy=multi-user.target
```

При первом запуске под systemd ссылка настройки будет в журнале:
`journalctl -u mabase`. Или заранее создайте администратора:
`./mabase superuser upsert`.

За обратным прокси (nginx, Caddy):
- проксируйте и `/api/realtime` - это WebSocket;
- включите `http: { trustProxy: true }`, чтобы лимиты считались по
  настоящему IP клиента;
- укажите `http: { serverUrl: 'https://my.app' }`, чтобы адреса возврата
  OAuth строились правильно.

Обслуживание:
- **Бэкап:** `./mabase backup /backups/$(date +%F)` - работает и на
  запущенном сервере. Или кнопка в админке.
- **Обновление:** `./mabase update`, потом перезапуск сервиса.
  Сверяется sha256 из `checksums.txt` того же релиза и проверяется, что новый
  файл запускается. **Подписи нет:** кто получил доступ к GitHub-аккаунту или
  CI, может выложить свой бинарник, и обновление его примет. Для своих
  проектов это осознанный компромисс; если нужно строже - ставьте
  `MABASE_UPDATE_URL` на свой сервер и обновляйтесь только с него.
- **Берегите `mb_data/secret.key`.** Без него сессии пользователей
  закончатся, а секреты в настройках придётся ввести заново.

## Надёжность и ограничения

Надёжность:
- **Запись подтверждается после fsync** строки журнала.
- **Транзакция атомарна**, даже если затрагивает несколько коллекций.
- **Падение процесса** в любой момент не теряет подтверждённое и не
  оставляет половину транзакции. Проверено тестами с `kill -9`.
- **Странные файлы базы** (например, нет `CURRENT`) - MaBase отказывается
  стартовать и ничего не удаляет.

Ограничения:
- **Вся база в памяти.** На документ - около 0.5 КБ кучи (сообщение чата),
  но резидентная память процесса выше. Замеры на 300 тыс. и 1 млн документов
  (снапшот 74 и 248 МБ): 300 тыс. - 144 МБ кучи, 550 МБ RSS, чтение 0.26 с;
  1 млн - 539 МБ кучи, 1.5 ГБ RSS, чтение 1 с и 1.5 с до готовности. VPS на
  1 ГБ хватает примерно до 300-400 тыс. документов, для миллиона нужно 2 ГБ.
- **Один процесс на папку данных.** Масштабирования и репликации нет.
- **Запись** - около 1700 транзакций в секунду с fsync, пачками - около
  80 тысяч документов в секунду.
- **Файлы:** лимит на файл - 100 МБ по умолчанию (`http.maxUploadBytes`);
  настройки S3 - только в конфиге/env, в админке их нет. Хранилище -
  локальная папка или S3; между ними переносит `mabase files migrate`.
- **Обновления без подписи.** `mabase update` проверяет sha256 и запуск
  бинарника, но не подпись - см. «Работа на сервере».

## Разработка MaBase

```
core/      MaBase: исходники (src/), тесты (test/), сборка (build.ts)
chat/      пример приложения: чат с комнатами, приглашениями и "печатает..."
design.md  решения и причины
```

Нужен [Bun](https://bun.sh) 1.3.12:

```bash
cd core && bun install
bun run test        # все тесты
bun run typecheck   # tsc --noEmit: strict + noUncheckedIndexedAccess
bun bench/realtime.ts 1000 10  # цена dependsOn: 1000 подписок, 10 пользователей
bun run build       # core/dist/mabase под эту машину
bun run release     # архивы под все платформы и checksums.txt
```

Проверка типов - в CI на каждой правке (`.github/workflows/ci.yml`). Раньше
`tsconfig.json` обещал `strict`, но ничего его не проверяло: Bun типы просто
вырезает.

Релиз выпускается тегом `vX.Y.Z`: GitHub Actions прогонит тесты, соберёт
архивы и выложит релиз. Номер версии - в `core/src/version.ts`, что нового -
в [CHANGELOG.md](CHANGELOG.md).
