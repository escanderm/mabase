# Изменения

## 0.2.9

- Проверка типов: `bun run typecheck` (`tsc --noEmit`, `strict` +
  `noUncheckedIndexedAccess`) на каждой правке в CI (оба окружения матрицы) и
  перед сборкой релиза.
- В devDependencies добавлены `typescript` и `@types/bun`: без них `tsc` не
  видел `Bun`, `process` и `node:*`, и «243 ошибки» были в основном этим, а не
  кодом.
- Разобраны все настоящие ошибки типов (24): сужение `Tx | null`, форма
  multipart (`string | File`), `Bun.serve` с лишним generic, `*.css`-импорт,
  `Uint8Array<ArrayBuffer>` в `Bun.CryptoHasher`/`gunzipSync`, частичные
  `SmtpOptions`/`S3Options` после слияния с env, `fetch` в SDK, типы в тестах.

## 0.2.8

- Настройки из окружения: фиксированный контракт `MABASE_*` с валидацией
  (числа, булевы, пути), неизвестная переменная - предупреждение, кривое
  значение - ошибка с именем переменной.
- Приоритет: флаги CLI > env > `mabase.config.ts` > админка > умолчания.
  Флаги теперь помнят, заданы ли они явно (`--port` перекрывает `MABASE_PORT`).
- Из env читаются порт/хост/папка/статика/адрес/CORS, S3 (по частям - остальное
  может быть в конфиге), SMTP и «от кого», адрес приложения и ключи
  Google/GitHub, `MABASE_SECRET`.
- `mabase config`: итоговые настройки с источником каждого значения, секреты
  замаскированы.
- `.env.example` - шаблон «одного файла» для локальной разработки и деплоя.
- Коллекции, правила, хуки и действия в env не переносятся: это код
  (`mabase.config.ts`), в env он превратился бы в нечитаемую простыню.

## 0.2.7

- Файлы можно хранить в S3-совместимом облаке (AWS, MinIO, Cloudflare R2,
  Яндекс): раздел `storage.s3` в `mabase.config.ts` - bucket, region, ключи,
  endpoint, prefix, forcePathStyle, sessionToken.
- Запросы к S3 подписываются AWS Signature V4 своим кодом, без зависимостей.
  Ключ объекта: `[prefix/]<коллекция>/<запись>/<id файла>-<имя>`; удаление
  записи удаляет объекты.
- Хранилище стало адаптером (`FileStorage`): локальный диск остаётся
  по умолчанию, S3 включается настройкой.
- Переключение хранилища не переносит уже загруженные файлы (в README прямо
  сказано и почему); команда переноса - позже.
- Проверено на фальшивом S3: подпись сверяется независимой реализацией
  (неверная - 403), загрузка/отдача/удаление идут через облако (тесты 191-193).

## 0.2.6

- Типизированный клиент без генерации кода: `createClient<typeof config>(url)`
  выводит коллекции и типы документов из zod-схем `defineCollection`, а
  `mb.action('имя', input)` проверяет вход по схеме `defineAction`.
- `defineCollection`, `defineAction` и `defineConfig` несут типы: имя коллекции
  и действия - литералами, схема - своим типом (а не `z.ZodType<Record<...>>`).
- В `mb_data/types.d.ts` появился модуль `mabase/client` с типами SDK:
  `MabaseClient`, `CollectionClient`, `Live`, `MabaseError`, `createClient<Config>`.
  В браузере `mabase/client` подключается import map или алиасом на `/api/client.js`.
- Проверено `tsc --strict` на сгенерированных типах: положительные случаи
  компилируются, неверные поля и несуществующие действия - ошибки.

## 0.2.5

- Горячая перезагрузка хуков: `mabase serve` следит за `mb_hooks/`, правка
  `*.ts` подхватывается без рестарта (пауза 150 мс после записи). Обработчики
  и `schedule()` собираются заново: удалённый файл перестаёт работать.
- Сломанный хук не роняет сервер: работают прежние обработчики, ошибка идёт в
  журнал и `tail`; после исправления файла перезагрузка произойдёт сама.
- `mabase.config.ts` по-прежнему требует рестарта (это осознанно: коллекции,
  индексы и правила меняются на ходу только из админки).

## 0.2.4

- `mabase migrate`: папка `mb_migrations/`, файлы `YYYYMMDDHHMM-имя.ts` с
  `export async function up(db)`. Порядок по имени, применённые - в
  `_migrations`, второй раз не выполняются. Каждая миграция - одна
  транзакция: упавшая посреди откатывается целиком, `down` нет.
- Периодические задачи: `schedule('digest.daily', '0 9 * * *', data?)` в
  конфиге или хуках. Cron из 5 полей (локальное время), задача в `_scheduled`
  с `key: cron:<событие>`, переживает перезапуск, просроченная выполняется при
  старте, после успеха получает следующее время.
- Проверено: разбор cron сверяется с полным перебором минут; упавшая миграция
  не оставляет ни документов, ни отметки; `mabase migrate` идемпотентен.

## 0.2.3

- Автодополнение в редакторе: при старте MaBase пишет `mb_data/types.d.ts` и
  рядом типы zod (вшиты в бинарник, 124 файла). `z`, `defineCollection`,
  `defineConfig`, `defineAction`, `defineSeed`, `on`, `mail`, `ActionError` и
  типы `Db`, `Hooks`, `Rules`, `files`, `origin` подсказываются без
  `node_modules`; переписывается только изменившееся.
- Проверено `tsc --strict` на примере конфига с коллекциями, правилами,
  хуками, действием и сидом: 0 ошибок.

## 0.2.2

- Файлы: поле-файл в коллекции (`files: { avatar: { maxBytes, accept, many } }`),
  загрузка в том же запросе, что и запись (`multipart/form-data`), метаданные в
  `_files`, байты в `<dataDir>/files/<collection>/<recordId>/`.
- Отдача `GET /api/files/:id` через правило `view` родительской записи;
  `?download=1` - вложением.
- Замена файла и удаление записи убирают старые файлы; лимиты
  `http.maxUploadBytes`, `files.<поле>.maxBytes` и `accept`.
- SDK: `insert(doc, { files })`, `update(id, update, { files })`, `fileUrl(id)`.
- Код ошибки `too_large` (413) для больших файлов и тел запросов.

## 0.2.1

Патч безопасности поверх 0.2.0. Данных и миграций не касается, но часть
клиентских запросов, которые раньше проходили, теперь получает 400: пути через
прототип (`__proto__`, `constructor`), `$set` вложенного поля через скаляр,
`$regex` с двумя повторами на точку. Поле из `owner` стало доступно только
серверу (хук, действие, сид).

Каждый пункт воспроизведён до исправления, на него есть тест.

- `$set`/`$unset`/`$inc`/`$push`, фильтр, сортировка и `fields` с `__proto__`
  (или `constructor`) больше не проходят: раньше любой вошедший мог записать
  в `Object.prototype` процесса и, подменив унаследованный `passwordHash`,
  войти в аккаунт без пароля (OAuth, телефон). Заодно `?fields=constructor`
  больше не даёт 500.
- Поле из `owner` клиент не пишет: `fields.private` больше не обходится
  сменой владельца записи.
- `$regex` от клиента: не больше одного повтора на точку (`.*a.*b` на строке
  в 1 МБ вешал единственный процесс). В `sort` и `fields` - не больше 8 полей.
- Смена пароля гасит и висящую ссылку смены email (жила 24 часа).
- Лимиты входа: отдельно по IP (10) и по аккаунту (50) - ротация адресов
  больше не снимает лимит, а чужой человек не запирает владельца.
- WebSocket перепроверяет сессию раз в 5 секунд (было - раз в минуту), а
  ошибка presence при подключении закрывает соединение, а не оставляет
  клиента в `connecting` навсегда.
- `mabase tail` и журнал админки не показывают токен из письма; значения в
  строке журнала экранируются.
- Ядро: ошибка проверки связи, пойманная в действии, отменяет транзакцию;
  индекс по числовому сегменту пути (`tags.0`) совпадает с перебором; цикл
  `after*` -> запись -> `after*` упирается в `maxDepth`.
- SDK: окно `live()` не растёт больше `maxLimit` (раньше перечитывание после
  `reset` однажды получало 400 и лента замирала навсегда); выход чистит живые
  выборки; `mb.on` одной и той же функции дважды больше не держит сокет
  навсегда; 409 при обновлении токена в двух вкладках не разлогинивает обе.
- Планировщик не запускает вторую копию обработчика, пока первая не
  завершилась (было: таймаут -> повтор через 5 с -> две копии параллельно).
- `tail` не растёт в памяти у медленного читателя: переполнение - пропуск с
  сообщением «skipped».
- Админка: `skip` ограничен, ключ с точкой (`secret.x`) больше не пишет
  скрытое поле; токен в браузере помнит, когда выдан, и стареет вместе с
  серверной сессией (7 дней).
- Схема на `update` больше не срезает поля, которых в ней нет: они просто не
  проверяются (новые поля вне схемы по-прежнему не появляются).
- Документ, созданный и удалённый в одной транзакции, не пишет no-op в лог и
  не даёт события `created` с `doc: null`.
- Компактирование публикует новое поколение до закрытия старого: ошибка
  `close`/`unlink` больше не оставляет в памяти старый лог.
- OAuth: переполнение начатых входов выбрасывает самый старый state, а не
  отказывает всем на 10 минут; очередь сообщений сокета ограничена 200.
- Хуки получают `origin`: `api`, `action`, `hook`, `seed`, `system`. Запись из
  хука помечена `hook`, поэтому хук может пропустить свои же изменения, а не
  защищаться флагом в документе или `depth`.

## 0.2.0

- Админка `/_/`: коллекции, документы (поиск с фильтром, правка, вставка,
  удаление), схема по данным, индексы, правила, журнал, бэкап.
- Коллекции из админки: создать с индексами, изменить индексы, удалить.
- Настройки в админке: способы входа пользователей (пароль, телефон,
  Google, GitHub) и почта. Хранятся в базе, секреты зашифрованы,
  применяются без перезапуска. Раздел в `mabase.config.ts` главнее.
- Первичная настройка при первом запуске: в терминале или по одноразовой
  ссылке в браузере - администратор, способы входа, почта.
- Администраторы входят по email и паролю.
  `mabase superuser list | upsert <email> <пароль> | delete <email>`.
- `bun run build` больше не убивает сервер, запущенный из `dist/mabase`.
- README переписан как техническое описание.
- Связи между коллекциями: `relations` в коде или вкладка "Связи" в
  админке. Проверка ссылок при записи, `onDelete` (`restrict`, `cascade`,
  `unset`, `pull`), `expand` в `find`/`get` и HTTP через правила доступа
  связанной коллекции. В админке - ссылки с именем документа и "кто
  ссылается".

## 0.1.1

- `mabase tail` больше не отваливается через 10 секунд, когда в базе ничего
  не происходит. Сервер раз в 5 секунд шлёт в поток пустую строку, иначе
  Bun.serve закрывал молчащее соединение.
- Чат-пример: если вход потерян (сессию отозвали, сервер подняли на другой
  базе), страница возвращается к форме входа, а не шлёт действия без токена.

## 0.1.0

Первый публичный релиз.

- Хранилище: журнал с fsync, атомарные транзакции на несколько коллекций,
  компактирование, бэкап на работающем сервере. Падение в любой момент не
  теряет подтверждённое (проверено `kill -9`).
- Документные коллекции: JSON-фильтры, операторы обновления, индексы с порядком, схемы на zod.
- Действия-транзакции, хуки `before*` и `after*`, события записей `on()`.
- Правила доступа-фильтры, `dependsOn`, поля `readonly`, `immutable`,
  `private`, `hidden`.
- Вход: пароль, телефон через authphone.su, Google и GitHub. Письма:
  подтверждение email, сброс пароля, смена email.
- HTTP API, WebSocket: живые выборки, presence, клиентские события.
- SDK для браузера прямо с сервера: `import { createClient } from '/api/client.js'`.
- Отложенные события: `emit(..., { after: '5m' })`, повторы, доставка минимум
  один раз.
- CLI: `serve`, `seed`, `backup`, `import`, `tail`, `update`, `version`.
- Сборки: macOS (arm64, x64), Linux (x64, arm64).
