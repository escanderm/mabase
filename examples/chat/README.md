# Пример: чат с закрытыми комнатами

> Код ещё не запускается. Это целевой API MaBase (`design.md` §19, шаг 3):
> так должен выглядеть проект, когда ядро будет готово. Работающий чат на
> этом коде - релиз v0.1 (шаг 9).

## Что умеет

- вход по паролю;
- комнаты: создать, переименовать, удалить (только владелец);
- приглашения: пригласить, принять; письмо о приглашении;
- выгнать участника, выйти самому;
- сообщения: последние 50, подгрузка старых при прокрутке, правка своих;
- "печатает..." и кто онлайн из моих контактов;
- после обрыва связи всё догоняется само.

## Что он проверяет в MaBase

| Что | Где в коде |
|---|---|
| Правила-фильтры: видно только свои комнаты и их сообщения | `mabase.config.ts`, `rules` |
| Правило зависит от другой коллекции, и доступ пропадает после `kick` | `messages.rules.list`, `kick` - **Q4** |
| Действия-транзакции вместо цепочек хуков | `createRoom`, `invite`, `acceptInvite`, `leaveRoom`, `kick`, `deleteRoom` |
| Отложенное событие в той же транзакции, доставка минимум один раз | `invite` + `mb_hooks/invite-email.ts` |
| Пагинация через индекс: `sort` + `limit` + курсор | `client/chat.ts`, `openRoom` |
| Клиентские эфемерные события | `typing` |
| Presence с правилами | `_presence` |
| Скрытые, неизменяемые и readonly поля | `fields` |
| Идемпотентный сид, 5000 сообщений пачками | `seed.ts` |

## Файлы

```

API-NOTES.md            что всплыло при написании - 12 вопросов к API
```
