# Прототип 01: один бинарник + внешние TS-хуки

Дата: 2026-10-29. Bun 1.3.12, macOS arm64.

## Вопрос

Может ли бинарник из `bun build --compile`:

1. подгрузить при старте внешние `.ts`-файлы из `mb_hooks/`;
2. отдать им свой API через `import { on, z } from 'mabase'` без `node_modules`;
3. отдать им свою копию zod;
4. подгрузить npm-пакет, если он лежит в `node_modules` проекта;
5. работать на машине, где Bun не установлен.

## Ответ: да, всё работает

| Что проверял | Результат |
|---|---|
| `import()` внешнего `.ts` из бинарника | Работает. TS транспилируется на лету: `interface`, `enum`, типы, top-level await |
| Хук импортирует соседний `../lib/helper.ts` | Работает |
| `import { on, z } from 'mabase'` без `node_modules` | Работает через `Bun.plugin` + `build.module('mabase', ...)` - виртуальный модуль |
| Все хуки получают один и тот же объект API | Да, обработчики из разных файлов лежат в одной шине |
| zod из бинарника, схема `instanceof` его же `ZodType` | `true` |
| Хук берёт **свою** копию zod из `node_modules` | Тоже `true`. zod 4 проверяет `instanceof` по признакам, а не по классу, так что две копии не ломают проверку |
| npm-пакет из `node_modules` проекта | Работает, ищется как обычно - от файла хука вверх |
| Пакета нет | Понятная ошибка с именем пакета и путём хука, остальные хуки грузятся |
| Чистое окружение: `env -i PATH=/usr/bin:/bin`, Bun не в PATH | Работает |
| Время старта (3 хука) | 20-30 мс. Первый запуск после сборки - около 170 мс на первом хуке |
| Размер бинарника | 59 МБ (у PocketBase около 30-40 МБ) |

## Подводный камень: подпись на macOS

Бинарник, который собирает Bun 1.3.12, **сразу убивается системой**
(exit 137, SIGKILL), даже пустой `console.log`. Причина: в файле есть секция
подписи, но она битая. Обычный `codesign -s -` падает с "invalid or
unsupported format for signature".

Помогает:

```bash
codesign --remove-signature dist/mabase
codesign -s - dist/mabase
```

Это уже вшито в `bun run build`. Для раздачи бинарника другим людям на macOS
понадобится нормальная подпись и нотаризация - как и у любой программы,
скачанной из интернета. Для Linux-сервера проблемы нет.

## Что НЕ проверено

- **Автодополнение в редакторе.** TypeScript локально нет, сеть была почти
  мёртвая. Но проблема видна и без проверки: в `mb_data/types.d.ts` сейчас
  стоит `typeof import('zod').z`. Если zod в проекте нет, редактор это не
  найдёт, и `z` станет `any`. Решение: бинарник кладёт рядом и типы zod.
  Это 102 файла, около 314 КБ (около 200 КБ без локалей и `zod/mini`).
  Терпимо, но это надо делать, а не "само заработает".
- **Сборка под Linux с Mac** (`--target=bun-linux-x64`): нужен интернет,
  чтобы скачать рантайм под другую платформу.
- **Перезагрузка хуков без рестарта** (как в PocketBase при изменении
  `pb_hooks`).
- **Node и Deno** - не проверял, см. ниже.

## Вывод для idea.md

Обещание "один бинарник, как PocketBase, + хуки на TS" на Bun выполнимо.
Схема:

- `mabase` - один файл, внутри Bun, zod и весь API;
- проект пользователя - `mb_hooks/*.ts` + `mb_data/`, без `package.json`;
- `import { on, z, defineCollection } from 'mabase'` в хуках;
- npm-пакеты - по желанию, через обычный `node_modules` рядом;
- бинарник пишет `mb_data/types.d.ts` и типы zod для редактора.

## А нужен ли вообще Bun

Пользователь справедливо спросил: в исходной идее Bun - не данность. Что
известно без проверки (отмечено, где я не уверен):

| | Bun | Node 24 + SEA | Deno |
|---|---|---|---|
| Один бинарник | `bun build --compile`, одна команда, проверено | SEA: несколько шагов (blob, postject, подпись) | `deno compile`, одна команда |
| TS-хуки без сборки | Да, проверено | Node 24 убирает типы сам, но `enum` и часть синтаксиса не поддерживает без флага | Да |
| `import()` внешних файлов из бинарника | Да, проверено | Не уверен, нужно проверять | Не уверен: compile по умолчанию ограничивает, что можно грузить снаружи |
| WebSocket-сервер встроенный | Да, с pub/sub | Нет, нужен пакет `ws` | Да |
| Зрелость, совместимость с npm | Хорошая, но бывают баги (как с подписью выше) | Лучшая | Хорошая, через `npm:` |

Моё мнение: Bun сейчас лучший выбор для этой идеи. Он закрывает сразу три
требования (один файл, TS без сборки, встроенный WS), и главное из них
проверено. Риск в том, что проект привязан к одному рантайму. Его стоит
принять осознанно и не держать "fallback на Node SEA" в документе: поддержка
двух рантаймов удвоит работу ради сценария, который, скорее всего, не
понадобится.

## Как повторить

```bash
bun run dev     # без компиляции
bun run build   # собрать и переподписать dist/mabase
bun run start   # запустить бинарник в project/
```
